# EvoData — корпоративний сайт

Статичний корпоративний сайт EvoData за ТЗ «Evo Data V1.1 без CMS».
Верстка виконана 1:1 з макета Figma.

**Стек:** Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS v4 · ESLint + Prettier.
Без CMS, бекенду, бази даних і серверної частини — увесь контент лежить у коді.

---

## Запуск

Потрібен **Node.js ≥ 20.9**.

```bash
npm install     # встановлення залежностей
npm run dev     # режим розробки → http://localhost:3000
```

## Збірка та продакшн

```bash
npm run build   # production-збірка
npm run start   # запуск зібраного застосунку → http://localhost:3000
```

Додаткові команди:

```bash
npm run lint         # ESLint
npm run typecheck    # перевірка типів TypeScript
npm run format       # форматування Prettier
```

## Змінні середовища

Скопіюйте `.env.example` у `.env.local` і заповніть значення:

| Змінна | Призначення |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Базова URL сайту — використовується для canonical, OpenGraph і `sitemap.xml` |
| `NEXT_PUBLIC_GA_ID` | Google Analytics 4. Якщо порожньо — скрипт не підключається |
| `NEXT_PUBLIC_META_PIXEL_ID` | Meta Pixel. Якщо порожньо — скрипт не підключається |

## Як змінювати контент

Проєкт свідомо розділяє **контент** і **розмітку**, щоб тексти можна було правити
без знання React.

| Що змінити | Де |
| --- | --- |
| Тексти сторінок | `src/content/en/*.ts` (наприклад `home.ts`) |
| Наскрізні тексти (футер) | `src/content/en/common.ts` |
| Телефон і e-mail | `src/config/contacts.ts` |
| Соцмережі, пункти меню | `src/config/site.ts` |
| Мови | `src/config/i18n.ts` |
| Кольори, шрифти, типографіка | `src/app/globals.css` (блок `@theme`) |
| Зображення, відео, шрифти | `public/images`, `public/videos`, `public/fonts` |
| SEO за замовчуванням | `src/app/layout.tsx` (об'єкт `metadata`) |
| Мапа сайту / robots | `src/app/sitemap.ts`, `src/app/robots.ts` |

### Заміна зображень

Файли лежать у `public/images/`. Достатньо покласти файл із тим самим ім'ям —
шляхи вказані у `src/content/en/*.ts`. Рекомендований формат — **WebP**.
Приклад конвертації (пакет `sharp` уже є в залежностях):

```bash
node -e "require('sharp')('in.png').resize(1800).webp({quality:85}).toFile('out.webp')"
```

### Телефон і e-mail: захист від спам-ботів

Значення лежать у **`src/config/contacts.ts`** — правити там, у звичайному
читабельному вигляді. Решта відбувається автоматично.

У віддану розмітку контакт потрапляє без `href` і спотвореним у три шари —
кожен доводиться знімати окремо (`src/lib/scramble.ts`):

1. **Перевернутий** (`moc.atadove@olleh`). CSS `unicode-bidi: bidi-override`
   розвертає його назад для ока.
2. **Без `@`, крапки і плюса** — саме вони роблять рядок схожим на адресу чи
   номер. У HTML на їх місці порожні `<span>`, а сам символ малює CSS
   (`.m-a`, `.m-b`, `.m-c` наприкінці `globals.css`). Збирачі адрес читають
   HTML, а не стилі.
3. **Із шумом.** Після кожних двох символів вставлено зайвий, прихований
   `display: none`. Бот, який усе-таки розверне рядок, забере правдоподібну,
   але неіснуючу адресу.

У підсумку в HTML немає ні `mailto:`, ні `@`, ні жодного рядка, схожого на
адресу чи телефон — перевірено `grep`ом по продакшн-збірці. Людина бачить
контакт правильно навіть із вимкненим JavaScript. Після гідратації
`ContactLink` збирає справжнє значення і робить його посиланням `mailto:` /
`tel:`, тож копіювання, клік і скрінрідери працюють як завжди.

Проти скрапера, який виконує JavaScript і дочікується гідратації, це не
захищає — таких меншість, і закритися від них повністю, не втративши
доступність, неможливо.

Три правила, щоб не зламати:

1. **`src/config/contacts.ts` не можна імпортувати в `"use client"`-компоненти** —
   інакше значення потраплять у JS-бандл. Тому їх і немає в `site.ts`, який
   тягне за собою інтерактивна шапка.
2. У `Organization` (`src/lib/schema.ts`) навмисно **немає** `email` і
   `telephone`: JSON-LD — найлегша здобич для збирача. Назва, URL, адреса та
   профілі лишилися.
3. Значення контакту не може містити `~`, `^` чи `*` — ці три символи
   використані як заглушки для `@`, `.` і `+`.

### Відео

Покладіть файл у `public/videos/` і вкажіть шлях у `src/content/en/home.ts` → `video.src`.
Від цього значення залежить поведінка блоку:

- `src` порожній (типово) — **секція не рендериться на жодній сторінці**
  (постер у макеті — стокова заглушка);
- `src` заданий — секція повертається скрізь, де її розміщено (головна,
  What we do, Industries, About us): показується постер із кнопкою,
  за кліком вмикається програвач.

## Мультимовність

ТЗ вимагає **архітектурної** підтримки: активна одна локаль (`en`), але всі тексти
винесені у `src/content/<locale>/`, а перелік мов — у `src/config/i18n.ts`.
Щоб додати мову: створити теку контенту, додати локаль у конфіг і (за потреби)
загорнути маршрути в сегмент `[lang]`.

## Якість

Lighthouse на продакшн-збірці (Performance / Accessibility / Best Practices / SEO):

| Сторінка | Mobile | Desktop |
| --- | --- | --- |
| `/` | 98 / 96 / 100 / 100 | 100 / 96 / 100 / 100 |
| `/what-we-do` | 98 / 97 / 100 / 100 | 99 / 97 / 100 / 100 |
| `/industries` | 95 / 97 / 100 / 100 | 99 / 97 / 100 / 100 |
| `/about` | 94 / 96 / 100 / 100 | 99 / 96 / 100 / 100 |
| `/faq` | 96 / 96 / 100 / 100 | 99 / 96 / 100 / 100 |

CLS скрізь 0. Найнижчий бал (`/about`, mobile) впирається у LCP 3.1 с — це 3D-об'єкт
у героєві внутрішніх сторінок (1600×1600).

Дві правки, які найбільше вплинули на результат — варто пам'ятати під час розробки:

- **`sizes` має відповідати реальному розміру зображення на екрані.** Завищене
  значення змушувало браузер тягнути надто великий варіант: LCP 3.6 с, Performance 90.
- **`size-[%]` рахує відсотки окремо від ширини й висоти** контейнера, тому квадратний
  3D-об'єкт у героях внутрішніх сторінок був спотвореним. Правильно — `w-[%] aspect-square`.

Адаптивність перевірено на 320 / 375 / 768 / 1024 / 1440 / 1920 px — горизонтального
переповнення немає на жодній ширині.

## Відкриті питання до дизайну

1. **Контраст.** `Let's talk` у футері (`white/50` на `#4264F6`, 2.32) не проходить
   WCAG AA. Залишено як у макеті — потрібне рішення дизайнера.
2. **Картку Case Study** (node `9165:260211`) з блоку «We develop and implement custom
   AI solutions…» прибрано: у текстах замовника («Главная страница.pdf», п. 5) її немає,
   а вміст у макеті — демонстраційний. Якщо блок кейсів потрібен — потрібні реальні тексти.
3. **Відео**: у макеті стокове зображення-заглушка. Потрібен фінальний постер і файл відео.
4. **Рядок переваг у Hero** зміщений на +7px (поля 64/50). Вирівняно симетрично від 64px.
5. **Куди ведуть пункти підменю.** Підменю реалізоване (nodes `9247:100973`,
   `9254:101016`), але окремих сторінок під 8 підпунктів у макеті немає, тому всі
   ведуть на батьківський розділ (`/what-we-do`, `/industries`). Якщо планувалися
   окремі сторінки або якорі — потрібен список адрес.
6. **Кнопки героя** («Book a Discovery Call», «Contact Us» на What We Do): у макеті
   видно лише текст 18px без явних стилів заливки. Використано стилі з компонент-сету
   `9423:1785` — варто звірити з дизайнером.
7. **Вкладки на What We Do** (секція `9325:1161`). Реалізовано те, що видиме в
   макеті: вступний текст «MVP Development» і під ним три вкладки (`9329:4288`) —
   Founders, Business Owners, CTOs. Вертикальний сайдбар (`9330:5345`) і ще дві
   вкладки («Testing, Validation…», «Deployment…») у Figma приховані й тексту не
   мають — якщо вони потрібні, потрібен контент і рішення, як їх показувати.
8. **Вкладки на Industries** (секція `9329:4329`) — під'єднана лише перша.
   Приховані фрейми цієї секції містять контент **зі сторінки What We Do**
   (MVP Development / For Founders / For Business Owners) — очевидно, залишки
   копіювання компонента: вони не відповідають підписам вкладок Industries
   («You Have a Product Idea…», «MVP Has Proven Demand…» тощо). Під'єднувати їх
   означало б показати чужий текст, тому решта вкладок неактивні до отримання
   правильного контенту.
9. **Слайдер «AI Solutions for Business Growth…»** (nodes `9420:1382`…`9420:1452`).
    У макеті перемикання між 6 напрямами позначене лише написом «(SCROLL)» —
    решта 5 слайдів лишалися непоміченими. Напис прибрано, додано стрілки та
    індикатори. Якщо дизайн передбачає інший вигляд контролів — потрібен макет.
10. **Ілюстрації слайдів 03 і 04** (`Computer Vision`, `Speech Recognition`) у макеті
    однакові (той самий `imageHash`) — імовірно, заглушка. Потрібне окреме зображення
    для 04.
11. **Картки «We develop and implement custom AI solutions…»** (node `9165:260193`)
    свідомо відходять від макета: у Figma картка горизонтальна (вертикальне фото
    ліворуч, текст праворуч), реалізовано фото зверху й текст під ним — на замовлення.
    Наповнення — п'ять напрямів із «Главная страница.pdf», п. 5, фото надані окремо.
12. **Порядок секцій на Industries.** У макеті білий блок «Our custom solutions»
    стоїть **над** синім героєм (y=0 проти y=699), хоча на всіх інших сторінках
    герой перший. Оскільки шапка прозора зі світлим текстом, над білим блоком вона
    була б нечитабельною, тож реалізовано звичний порядок: герой → контент.
13. **П'ята картка «Custom AI solutions for business»** — `Data-Driven Decision
    Making`. У макеті (`9320:78046`) карток чотири, у текстах замовника
    («What we do.pdf», п. 4) — п'ять. Реалізовано п'ять; фото надані окремо.
14. **Заголовок «Everything you need to now»** у макеті (`9241:24297` і
    `9329:4121`) — одруківка. На сайті виправлено на «know».
